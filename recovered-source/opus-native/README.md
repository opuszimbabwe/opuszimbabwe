# Opus Inbox desktop and Android packages

Android: signed release APK, package zw.co.opuszim.inbox, version 1.0.0, Android 6+ and current Chrome. Uses a Trusted Web Activity with a verified website association; browser UI may appear during external Cloudflare sign-in. No credentials are bundled. Existing website auth and Chrome push permissions apply. The signing key and password are stored with owner-only permissions under android/release-signing.p12 and android/signing-password. The encrypted PKCS12 is also backed up in private R2 at private-signing/opus-inbox-release-1.p12, with its password in the encrypted OPUS_ANDROID_SIGNING_PASSWORD Worker binding. Keep both in a secure backup to sign future updates; never distribute them with sources or upload them to the website.

Windows: x64 Windows 10/11 installer, per-user installation and standard uninstall entry. Native Electron shell, sandboxed/context isolated; website has no Node access. Sign-in remains required. External links open in the browser. Product icon and version resources are embedded. No commercial publisher certificate is configured, so Windows may display an unknown publisher warning. Windows 1.0.2 supersedes the original close behavior: closing the window hides to tray and retains the authenticated live connection. Explicit Quit exits. Browser/Android background delivery uses Web Push.

Web UI updates load from the live website and can be checked through Settings. Native runtime updates require downloading a new package. Neither binary has been installed on a physical Android or Windows device in this Linux build environment. APK cryptographic signatures, Android manifest/DEX and Windows executable/resources/installer structure are checked here. Mobile/desktop web layouts are browser tested.

Build Android with ECJ and Android API35 build tools: compile Java against android.jar, d8 --min-api23, aapt package resources/manifest, add classes.dex, zipalign, then apksigner with the preserved release key. Build Windows: npm ci; electron-builder --win --x64 --dir; node brand-exe.mjs; compile installer.nsi with Linux makensis. The custom NSIS installer avoids Wine and contains the actual Windows runtime. Do not distribute node_modules, signing keys or passwords. installers are stored in existing private R2 under app-releases and downloaded only after admin authentication.
