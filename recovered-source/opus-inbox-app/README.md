# Opus Inbox

Live installable web app: https://opuszim.co.zw/sysadmin/mobile/

Sign in with the existing authorised Opus admin account. On Android, use Install app / browser menu. On iPhone, open in Safari and use Share → Add to Home Screen, then open the installed icon. Tap Enable alerts and grant the OS permission. Test phone alert creates one clearly labelled Website Inbox test and invokes the existing phone/email alert workflow.

app.html, app.css, app.js are the UI sources. Run python build-module.py to regenerate admin-app.mjs. The delivery Worker imports that module. The original notifications worker source is combined with narrow offline shell caching. Do not cache private APIs or customer data. Keep the original root service-worker subscription key/configuration, Access rules and admin API authorization.

test-server.mjs and check-app.cjs are local-only fixtures (port 9899), with no real customers or notification sends. Production user-authenticated data is not available to these fixtures. Phones need actual internet access; mobile-data enabled without a valid data allowance does not establish connectivity, and WhatsApp-only bundles may exclude this app. Push payloads are small but protocol/OS network overhead and opening an enquiry exceed a fixed 1 KB.

## Consolidated conversations, Feedback and resilient sending (v9)
Customer Conversations navigation group removed from the audited main dashboard client. Sidebar footer has one Open Inbox app link. Old webchat/feedback tool URLs redirect to the canonical app (feedback deep link supported). Legacy WhatsApp tool remains reachable through the app channel link. Main-dashboard unread summary polling is now disabled outside explicit legacy conversation-tool pages. Original customer records and backend APIs are preserved.

Feedback is available in mobile bottom navigation and desktop rail. Uses existing /api/admin/feedback GET/POST protocol, latest 100 responses, local search and All/New/Reviewed filters; review/reopen retains original comments. Fetches lazily on entry, coalesces foreground reads for 30 seconds, and does not poll or query chat while Feedback is open. Existing site_feedback_recent index covers the backend recency view. Expired-session lock clears feedback rows and all in-memory messages.

Enter now sends in both staff and website team chat. Shift+Enter adds a line and continues quote/list prefixes. IME composition does not trigger sending. Shared navigation parent supports Feedback without duplicate rails. Chat button/glyph background and box shadow are explicitly transparent in both themes; filled bubble, internal lines and unread badge remain.

Normal outgoing messages immediately render a pending bubble and clear the composer. Staff and visitors can queue another message during confirmation. Staff in-memory outbox processes sequentially, retries transient network/408/429/5xx failures with bounded backoff and original UUID, and resumes offline entries on reconnect. Sending/retrying/queued/failed/saved are distinguished; a saved check appears only after backend acceptance. HTML gateway failures and incomplete JSON are retryable, not false authentication expiry. Failed text/metadata remain available for retry; new typing is preserved. Sending no longer waits for a follow-up inbox reload. Visitor transport has matching UUID-preserving bounded retries and session-preparation recovery. Website refreshes coalesce overlapping sends. Normal AI questions are still not forwarded.

Outbox/drafts are memory-only: keep the app/tab open until confirmation. Closing/reloading before an unconfirmed send completes does not preserve the local pending queue. Private messages/APIs are not stored in Cache Storage. Generic KaTeX library is cached on first controlled use and a failed library load can retry after reconnection.

Worker request context.waitUntil runs email notification work after the original message API accepts, without holding the customer HTTP confirmation. Provider idempotency key remains tied to the message UUID. Rich/plain human chat messages notify the configured admin; normal /api/assistant calls do not. Existing native push and encrypted bindings are retained.

Validation: check-feedback, check-fast-send, check-visitor-send, check-composer, check-inline-icons, check-viewport, check-rich, check-app, admin nav/unit/Worker tests, and notification-background test passed. Network-hold tests prove optimistic display before acknowledgment, multiple queued messages, same-ID retries, reconnection resume, and no premature saved check. Live website handoff regression uses mocked side-effect endpoints. Production smoke checks confirm shell v9, protected app/feedback endpoints and retained D1/R2/notification bindings.
